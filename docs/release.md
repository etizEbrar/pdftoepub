## Blocking: the app has no server to talk to

`PRODUCTION_BACKEND_URL` in `ios/project.yml` is empty because no backend is
deployed. A Release build therefore starts with no address and asks the user for
one.

This is correct behaviour, but it is **not submittable as-is**. An App Store
reviewer has no conversion server, so they cannot convert anything, and the app
would be rejected under Guideline 2.1 (App Completeness) or 4.2 (Minimum
Functionality).

Two ways forward, both requiring a decision that isn't a code change:

1. **Deploy a public backend.** Host `backend/` behind HTTPS, then set
   `PRODUCTION_BACKEND_URL` to that address (in `project.yml`, or by passing
   `PRODUCTION_BACKEND_URL=https://…` to `xcodebuild`). The app validates that
   the value is neither empty nor a private address before using it.
2. **Ship it as a bring-your-own-server client**, and say so plainly in the App
   Store description and review notes, supplying the reviewer with a working
   server address. Apps in this category are accepted, but the reviewer must be
   able to reach a running instance during review.

The address field already accepts a LAN address in Release, so option 2 works
without further code changes. Plain `http` is rejected for public hosts, so a
public deployment must be HTTPS.

Still required, and obtainable only by the account holder:

  `xcrun notarytool store-credentials`. Without one, `xcrun altool
  --upload-app` and TestFlight distribution cannot run.
- **An app record** in App Store Connect for bundle ID `com.pdftoepub.app`.
  The archive is signed for team `23766BZUS5`; the record must belong to it.

## App Store Connect metadata still to author

None of this exists yet, and none of it should be invented:

- Privacy policy URL — **required for every app**, no exceptions.
- Support URL.
- App name, subtitle, description, keywords, primary category.
- Screenshots for 6.9" iPhone **and** iPad — the build declares
  `TARGETED_DEVICE_FAMILY = 1,2`, so iPad screenshots are mandatory. Dropping
  iPad from the target removes that requirement.
- Age rating questionnaire.
- App Privacy answers. They must match `PrivacyInfo.xcprivacy`: no tracking, no
  collected data types.

Export compliance is already answered in the build:
`ITSAppUsesNonExemptEncryption = false`.
